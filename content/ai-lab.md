# AI Drafting Lab for Transition and Special Education Work

Status: revised for the requested screening and workflow fixes

## Privacy-screen boundary

The lab is the next step when staff are considering a careful, approved use. Its browser-based checks are a teaching and review aid, not a FERPA compliance decision. All three drafting areas use the same identifier checks; the area changes drafting tasks and educator review emphasis.

Possible identifiers must be removed or generalized before generation. Sensitive-content findings require contextual review: remove private medical, disability, family, and employer details; retain only the minimum functional information permitted for this task. The checker does not recognize every name, language, address format, medical term, or locally identifying combination. Changing capitalization does not remove an identifier.

“No identifiers detected by these checks” does not establish de-identification. This screen cannot guarantee that text is safe to share. Before generation, educators must confirm: I reviewed names and places, sensitive details, and combinations such as exact schedules, small groups, unusual events, and distinctive support needs. I removed or generalized details that could identify someone and kept only information permitted for this task and approved tool.

Use the minimum information needed. District approval is not blanket permission to paste every detail from a student record. Generated prompts describe the material as source notes, without certifying it as de-identified.

## Browser-only workflow

Choose an area, enter draft text, review every finding, revise, complete contextual review, choose a task, and generate. Source edits, area changes, task changes, and re-checking clear old output. Source edits, area changes, and re-checking also reset contextual review. Copy reports actual success or selects the prompt for manual copying if automatic copying fails. Clear removes source, findings, review confirmation, and output and restores the first area and task.

The lab has no native HTML form submission path. Source text has no name attribute. Input and generation remain disabled until screening and event handlers initialize successfully. If screening is unavailable, the page says: “Screening unavailable. Text entry and generation are disabled. Enable JavaScript and reload; if this message remains, try again later.” No source text is stored or transmitted by the lab; copying is an explicit user action.
